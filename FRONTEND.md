# FRONTEND.md

Правила работы над внешним видом FieldLog (workflow_monitoring). Читается перед любой фронт-задачей.
Архитектура приложения, модели и маршруты — в `CLAUDE.md`; здесь только то, что касается интерфейса.

Область действия: `signal1520/templates/`, `authentication/templates/`, `templates/403.html`,
`signal1520/static/signal1520/css/`, `signal1520/static/signal1520/js/`, `authentication/static/authentication/css/`.

## Принятые решения (2026-10-05)

| Вопрос | Решение |
|---|---|
| Навигация | Обычные серверные страницы и ссылки. Подгрузки контента через AJAX (`contentPanel`) нет и возвращать её не нужно |
| Каркас | Один `signal1520/base.html`: шапка, панель значков слева, футер. Его наследуют и страницы организации, и страницы профиля |
| Шапка | Слева текстовый логотип FieldLog (ссылка на главную), справа «Имя \| Организация» и «Выйти» |
| Меню | Панель значков; клик по значку раскрывает вправо ряд кнопок-разделов той же высоты, вплотную к значку, поверх страницы. Клик мимо или `Esc` сворачивает |
| Значки меню | Inline-SVG с обводкой `currentColor`, как в `quiz_project`. В меню, шапке и футере — без эмодзи |
| Профиль в меню | Значки «Мой профиль» (профиль, редактирование, все пользователи) и «Настройки» (смена пароля, политика конфиденциальности) |
| Без организации | В меню только «Мой профиль» и «Настройки», логотип ведёт на профиль |
| Вход и регистрация | Отдельные экраны без шапки и меню |
| Политика конфиденциальности | Отдельная страница без каркаса и без кнопки возврата; открывается в новой вкладке |
| «Нет прав» | Одна карточка `templates/403.html` на все случаи; текст про чужую организацию — только при заходе в чужую организацию |
| Поиск и пагинация | Без JavaScript: GET-форма и ссылки `?page=N`, страница перезагружается |
| Телефон (до 768px) | Панель значков скрыта, в шапке бургер; он открывает сразу весь список: группа со значком и под ней её разделы |
| Таблицы на телефоне | Задачи: ID, Статус, Станция, Описание (обрезается многоточием). Объекты: Наименование, Дорога/Регион, Задачи. Остальные списки прокручиваются вбок внутри своего блока |
| Подтверждения | Спорные решения по виду и поведению Claude уточняет **до** реализации, в чате, по одному вопросу (варианты А/Б с рекомендацией) |

## Стек и ограничения

- Django Templates + чистый CSS + ванильный JS. Без фреймворков, сборщиков, npm и CDN.
- Шрифты и иконки — без внешних запросов: `Arial, sans-serif`, inline-SVG.
- Подключение любого внешнего сервиса (CDN, шрифты, карты, аналитика) требует обновления политики
  конфиденциальности до выката — см. раздел «Персональные данные» в `CLAUDE.md`.
- Тема одна (светлая).

### Адаптив

- `<meta name="viewport">` стоит в `base.html`, `403.html`, `login`, `register`, `locked_out`, `privacy_policy`.
  Новой самостоятельной странице он нужен обязательно, иначе телефон покажет её как уменьшенную страницу для компьютера.
- Одна граница — `@media (max-width: 768px)`. Правила каркаса для телефона — в конце `styles.css`, списков — в конце `styles_stations.css`.
- На телефоне `.main-layout` — обычный блок, страница в одну колонку; горизонтального скролла страницы быть не должно,
  широкая таблица прокручивается внутри `.table-wrapper`.
- Меню: `#nav-toggle` (бургер в шапке) переключает класс `.is-open` на `#side-rail`. Кнопки групп `.rail-btn` на телефоне —
  заголовки (`pointer-events: none`) с подписью `.rail-label`, ряды `.rail-flyout` показаны всегда столбиком.
- Таблица с классом `.table-compact` на телефоне скрывает ячейки `.col-desktop` и сжимается под экран;
  `.task-desc-cell` занимает остаток ширины и обрезается многоточием.
- Ширина поля поиска и flex-ряд в `.stations-header` заданы в шаблонах inline, поэтому мобильные правила для них — с `!important`.
- Проверка без телефона: окно браузера может не сжиматься, тогда страницу удобно загрузить в `<iframe srcdoc>` шириной 390px
  (обычный `src` не сработает: Django отдаёт `X-Frame-Options: DENY`).
- После правки CSS браузер держит старый файл в кэше — проверять с Ctrl+F5.
- **Кэш на проде.** Nginx отдаёт `/static/` с `expires 30d` и `immutable`, имена файлов не меняются. Поэтому в `base.html`
  у `styles.css`, `styles_stations.css`, `sidebar.js`, `instructions.js` стоит `?v=ГГГГММДД`. При любой правке этих файлов
  номер нужно поднять, иначе пользователи до месяца будут видеть новую разметку со старыми стилями.

## Дизайн-система

Название продукта в интерфейсе — **FieldLog** (логотип в шапке: «Field» белым, «Log» бирюзовым).

| Группа | Значения |
|---|---|
| Основные цвета | `#00B7B7` (бирюзовый), `#333333` (тёмно-серый). Фиолетовый `#667eea` не используется |
| Фон страницы | `linear-gradient(135deg, #333333 0%, #00B7B7 100%)` на `body` |
| Шапка и панель значков | фон `#333333`, значок `#cfd8dc`, текущий раздел `#00B7B7`, раскрытый значок и его кнопки — фон `#00B7B7`, текст белый, наведение `#009999` |
| Поверхность | белая карточка, скругление 8–20px, тень |
| Текст | `#2c3e50` (заголовки), `#333` (основной), `#7f8c8d` / `#95a5a6` (приглушённый) |
| Состояния | успех `#27ae60`, ошибка `#e74c3c`, предупреждение `#f39c12`, инфо `#3498db` |
| Строки задач | выполнена `#d5f5e3`, срок истёк `#fadbd8`, срок менее 30 дней `#fff176` |
| Размеры каркаса | `--header-height: 56px`, `--rail-width: 64px`, `--rail-btn-size: 46px` — блок `:root` в `styles.css` |

CSS-переменные заведены только для размеров каркаса; цвета пока записаны значениями прямо в правилах.

### Организация CSS

- `styles.css` — каркас: `body`, шапка, панель значков, футер, `.button`, общие таблицы, `.user-info`.
- `styles_stations.css` — списки: `.stations-container`, `.stations-header`, `.stations-table`, `.btn-create`,
  `.back-link`, `.pagination`, `.pagination-btn`, `.pagination-info`, `.empty-state`.
- `auth_styles.css` — экраны входа и регистрации (`.auth-*`, `.btn-auth`, `.hp-field`); подключается и на страницах профиля.
- Оба файла signal1520 подключены в `base.html` один раз.
- У форм и карточек стили лежат в `<style>` внутри шаблона (в `{% block extra_head %}` или в начале `{% block content %}`).
  Это текущее состояние, а не правило: общее выносить в CSS-файлы по мере переделки страниц.

### Классы каркаса — глобальные

`.site-header`, `.logo`, `.header-right`, `.logout-btn`, `.user-info`, `.side-rail`, `.rail-group`, `.rail-btn`,
`.rail-icon`, `.rail-flyout`, `.flyout-link`, `.main-layout`, `.page-content`, `.welcome-panel`.

Их имена нельзя переиспользовать в `<style>` страниц: стиль страницы перебьёт каркас. Так уже было
с `.header-btn` (занят страницей смены пароля), поэтому кнопка выхода называется `.logout-btn`.

Обратная ловушка — правила по тегам в `styles.css` (`table`, `th, td`, `tr:hover`): они действуют на любую страницу каркаса.

### Компоненты

- **Шапка** — `.site-header` (фиксированная), `.logo`, `.user-info` (`.user-name`, `.user-org-divider`, `.user-org`), `.logout-btn`.
- **Панель значков** — `.side-rail` → `.rail-group` → `button.rail-btn` (`aria-controls`, `aria-expanded`, `title`)
  + `.rail-flyout` (неподвижное окно-обрезка) → `.flyout-row` (едет через `transform`) → `a.flyout-link`.
  Анимация раскрытия — одно движение ряда целиком, 0.45s с торможением в конце; вариант «кнопки по очереди»
  пользователь отверг как дёрганый. Неактивный пункт — `span.flyout-link.is-disabled`. Текущий раздел — `.rail-btn.is-current`.
- **Страница** — содержимое в `<div class="page-content">`: растягивается на всю ширину справа от панели.
- **Список** — `.stations-container` → `.stations-header` (заголовок, поиск, кнопки) → `.table-and-pagination`
  → `.table-wrapper` + `.stations-table` → `.pagination`.
- **Кнопки** — `.btn-create` (главное действие в списке), `.back-link` (серая), `.pagination-btn`,
  `.btn-submit` / `.btn-cancel` (формы), `.button` (футер).
- **Карточка объекта** — шапка с градиентом `#00B7B7 → #333333`, `.info-grid` из `.info-card`
  (`.info-label` + `.info-value`), `.section-title`.
- **Форма** — `.form-container` → `.form-header` → `.form-body` → `.form-group`, `.error-message`, `.help-text`, `.form-actions`.
- **Тосты** — `#toast-container` + `.toast.toast-<уровень>`; сейчас есть только на главной (`index.html`).
- **«Нет прав»** — `templates/403.html`, самостоятельная страница с карточкой `.card`.

## Контракты с бэкендом — не ломать

Менять внешний вид и структуру разметки можно свободно. Перечисленное ниже нельзя переименовывать,
удалять или переносить без согласования: на это завязаны вьюхи, JS или тесты.

### Общее

- В каждой `<form method="post">` — `{% csrf_token %}`.
- `name` полей, `action` и `method` форм не менять. Поля рендерить через объекты формы Django
  (`{{ form.field }}`, `{{ form.field.errors }}`).
- Все `{% url %}` маршрутов signal1520 — с `org_slug=org_slug`. Переменную даёт context processor:
  из URL, а на страницах `/accounts/...` — из профиля пользователя. Пустая строка означает «организации нет»,
  поэтому ссылки на разделы организации вне `/<org_slug>/` оборачивать в `{% if org_slug %}`.
- Имена маршрутов и переменных контекста не менять.
- Не добавлять в шаблоны логику доступа сверх той, что уже приходит из вьюх (`can_add_warehouse`, `can_edit`,
  `can_add_equipment`, `can_add_type`, `perms.*`).
- Вне организации на странице нельзя называть переменную цикла `user`: каркас берёт из неё имя в шапку
  (в `users_list.html` и `user_detail.html` для этого используется `user_obj`).

### `signal1520/base.html` и `_sidebar.html`

- Блоки `{% block title %}`, `{% block extra_head %}`, `{% block content %}`.
- `#side-rail`, `.rail-group`, `.rail-btn[aria-controls]` → `id` соответствующего `.rail-flyout`, класс `.is-open`,
  атрибут `aria-expanded` — связка для `sidebar.js`.
- Подсветка текущего раздела — по `request.resolver_match.url_name` в `_sidebar.html`. При добавлении маршрута
  в раздел его имя нужно дописать в строку `{% if name in '...' %}` нужного значка.
- Разделы организации в меню и ссылка «Связаться с поддержкой» — внутри `{% if org_slug %}`.
- Выход — ссылка на `authentication:logout` (вьюха принимает GET).
- Ссылка на политику конфиденциальности — с `target="_blank" rel="noopener"`.

### Скрипты

| Файл | На что завязан |
|---|---|
| `sidebar.js` | см. выше |
| `stations.js` | `.tasks-toggle-btn` + `data-station-id`, список `#tasks-<id>`, `.toggle-icon`. Подключается только в `station_list.html` |
| `instructions.js` | `.btn-delete[data-url][data-pk]`, строки `[data-row-pk]`, заголовок `.link-title` или `strong`; cookie `csrftoken` |
| `alarm_toggle.js` | `.explanation-cell` → `.explanation-short`, `.explanation-full`, `.explanation-toggle` |
| `form_validation.js` | `validateForm('<id формы>', [{ id: 'id_<поле>', ... }])` — вызывается inline в конце шаблонов форм; класс `.input-error` |

Скрипты страницы выполняются один раз при загрузке, поэтому inline-`<script>` в шаблонах допустим.
`stations.js` и `instructions.js` сами запускают себя на `DOMContentLoaded`.

### Списки

- Форма поиска: `method="get"`, поле `name="search"`; сброс — ссылка `?`.
- Пагинация: ссылки `?page=N&search=...`.
- Кнопка «Выгрузить» — обычная ссылка на маршрут экспорта.

### Карточка задачи — `bug_details.html`

- `#status-container`, `#status-badge` (`data-status`), `#change-status-btn`: смена статуса — `fetch` POST
  с JSON `{status}` на адрес страницы; ответ `{success, status, status_display}`, после успеха страница перезагружается.
  Список статусов в выпадающем списке берётся из `#allowed-statuses` (`json_script` из переменной `allowed_statuses`).
  Кнопка показывается при `can_manage`; без доступных переходов она `disabled` с классом `.is-locked`.
- `#status-change-info` — дата, время и автор последней смены статуса (`last_status_change`).
- У закрытой задачи: поля вложения в `fieldset.attachment-fields[disabled]` при `not can_attach` — для всех, включая
  суперпользователя; «Редактировать задачу» — `span.back-link.is-locked` вместо ссылки при `not can_edit_task`
  (не для суперпользователя). На заблокированном — курсор `not-allowed`. Комментарии не блокируются.
- Правка комментария: у комментария с `comment.can_edit` (ставит вьюха: автор, 24 часа с создания) — кнопка
  `.comment-edit-btn[data-comment-id]`, текст `#comment-body-<id>` и скрытая форма `#comment-edit-form-<id>`
  с полями `edit_comment_id` и `edit_comment_text`. Пометка «изменён» — `.comment-edited` при `comment.is_edited`.
  Удаления комментариев нет — так решено.
- `#comment-form` с `textarea[name="comment_text"]`; `#attachment-form` с `input[name="file"]` и `textarea[name="description"]`.
- `.view-image-link` + `data-image-url` — просмотр изображения в модальном окне `.modal` (z-index 1000, выше каркаса).

### Формы объектов — `station_form.html`, `station_update_form.html`

- Проверка дубликатов названия ходит на `signal1520:station_check_name` с заголовком `X-Requested-With`.
  Список дубликатов строится через DOM API (`createElement` + `textContent`), не через `innerHTML`.

### Регистрация — `authentication/register.html`

- `#submit-btn`, чекбокс `privacy_policy`.
- Honeypot-поле `website` (`.hp-field`) остаётся в разметке и невидимо для человека.

### Профиль — `about_me.html`

- Плашка `.pending-banner` показывается, пока у пользователя нет организации.

### Политика конфиденциальности

- При любом изменении **текста** политики поднимать `POLICY_VERSION` в `authentication/views.py` и версию
  в шапке шаблона. Правка оформления версию не меняет.

## Проверка

- Тесты проверяют ответы сервера, но не внешний вид: после правки вёрстки страницу нужно открыть в браузере.

## Что не доделано

- Эмодзи в содержимом страниц (заголовки списков, кнопки на карточках и в формах) — убраны только из меню, шапки и футера.
- Кнопки «В главное меню» со списков и карточек убраны (на главную ведёт логотип). Остались ссылки на главную
  в роли «Отмена» в формах, «← Главное меню» в форме обратной связи и на странице лимита инструкций.
- Главная (`index.html`) — сводка: плитки `.stat-card` в сетке `.stat-grid` (мои задачи, задачи организации, объекты,
  оборудование, склады). У плиток задач — метки `.stat-chip`: просрочено, срок менее 30 дней, выполнено.
  Цифры считает `TasksIndexView`; плитка показывается только при праве на соответствующий раздел.
  Блок «Мои ближайшие задачи» пользователь попробовал и убрал — не возвращать.
- Лента «Последние изменения» под плитками (решено 2026-10-07): `.activity` → `.activity-list` → `a.activity-row`
  (`.activity-time`, `.activity-user`, `.activity-text`). Одна строка на событие: «07.10 15:25 · имя · что произошло»,
  без текста комментариев; вся строка — ссылка на задачу или объект (`.is-gone` без `href`, если объект удалён).
  Блок занимает остаток высоты до футера и показывает только целые строки, без прокрутки: `.activity-list` —
  колонка с `flex-wrap: wrap` и `overflow: hidden`, не поместившиеся строки уходят во вторую колонку за правым краем.
  JS не используется. Минимум — три строки (тогда страница прокручивается). На телефоне — пять последних, текст переносится.
- Раскладка страницы: списки и карточки — на всю ширину и высоту до футера (первый `div` внутри `.page-content` растягивается);
  формы (`.form-container`) — по центру, не шире 800px, высотой по содержимому. Ограничения ширины у `body` нет.
- Между 769px и ~900px (планшет вертикально) действует вид для компьютера: ряд из трёх кнопок-разделов может не поместиться по ширине.
- Мобильный вид проверен в рамке 390px в Chrome на компьютере, на настоящем телефоне — нет.
- Цвета не вынесены в CSS-переменные; большая часть стилей форм и карточек — в `<style>` шаблонов.
- Шаблон `bug_list_ajax.html` нигде не используется.
- В меню показываются все разделы независимо от прав пользователя; без права раздел открывает карточку «Нет прав».
